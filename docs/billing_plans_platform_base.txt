Current behavior:
El servicio funcionaba como API stateless de IA, sin base de datos, SQLAlchemy,
Alembic, suscripciones, planes ni consumos persistidos.

Proposed behavior:
El servicio pasa a ser la base de postas_platform_api y expone endpoints
internos para consultar permisos y registrar consumos de tenants.

Implementation plan:
1. Agregar configuracion de plataforma, base de datos sync y Alembic.
2. Crear modelos SQLAlchemy para planes, features, suscripciones, pagos y usage.
3. Implementar seed idempotente del catalogo inicial.
4. Agregar servicios y endpoints internos bajo /internal/v1.
5. Cubrir seed, permisos, consumo, idempotencia y seguridad con tests.
6. Documentar migraciones, seed, seguridad y ejemplos curl.
